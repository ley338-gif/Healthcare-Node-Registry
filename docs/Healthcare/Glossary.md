# Healthcare- und Domänen-Glossar

| Begriff | Verbindliche Bedeutung |
|---|---|
| Asset/System | physisches oder logisches IT-System, zum Beispiel Modalität, PACS, RIS, Archiv oder Viewer |
| Gerät | physische technische Einheit; kann ein Asset darstellen, ist aber nicht automatisch ein DICOM-Endpoint |
| Endpoint | konkrete technische Kommunikationsadresse eines Assets |
| DICOM Application Entity | konkreter DICOM-Endpoint mit AE Title, Host/IP, Port und Diensten |
| DICOM Node | umgangssprachlicher Begriff; im Datenmodell nicht als Ersatz für Asset oder Endpoint verwenden |
| Connection | gerichtete, dokumentierte Beziehung zwischen einem Quell- und Zielendpoint |
| Service | fachlich-technischer Kommunikationsdienst, zum Beispiel C-STORE, MWL oder HL7-ADT |
| SCU | DICOM Service Class User für einen konkreten Dienst |
| SCP | DICOM Service Class Provider für einen konkreten Dienst |
| Called AE | Ziel-AE-Title einer konkreten DICOM-Kommunikation |
| Calling AE | Quell-AE-Title einer konkreten DICOM-Kommunikation |
| Organization | fachlich dokumentierte Organisation innerhalb einer Installation; kein automatischer technischer Tenant |
| Site | Standort einer Organisation |
| Department | organisatorische Einheit an einem Standort |
| Responsibility | dokumentierte technische, fachliche, betriebliche oder Herstellerverantwortung |
| Documentation State | Qualität/Freigabe der Dokumentation: draft, reviewed, approved, deprecated, archived |
| Operational Intent | dokumentierte Soll-Nutzung: planned, active, inactive, unknown; kein gemessener Live-Status |
| Audit Event | unveränderlicher fachlicher Nachweis einer relevanten Aktion |
| Technical Log | Betriebs- oder Fehlerprotokoll; nicht mit Audit Events vermischen |
| Security Event | sicherheitsrelevantes Ereignis, zum Beispiel fehlgeschlagene Anmeldung oder Rollenänderung |
| Patientendaten | personenbezogene Gesundheitsinformationen; für den Registry-Kern nicht erforderlich |
