# Quality Objectives

## QO-001 Nachvollziehbarkeit

100 % der Releases besitzen Changelog, Release Notes und dokumentierte Migrationen.

## QO-002 Testqualität

Kritische Autorisierungs- und Geschäftsregeln besitzen automatisierte Tests. Reine Coverage-Prozentwerte ersetzen keine risikobasierte Testauswahl.

## QO-003 Dokumentationsaktualität

Keine Version wird freigegeben, wenn Installation, Update, Backup oder betroffene Fachunterlagen nachweislich veraltet sind.

## QO-004 Sicherheit

Keine bekannte kritische oder hohe ungeklärte Schwachstelle im Release. Ausnahmen benötigen dokumentierte Risikoakzeptanz.

## QO-005 Wiederherstellbarkeit

Vor produktiver Freigabe wird ein Restore aus einem realistischen Backup erfolgreich getestet und protokolliert.

## QO-006 Bedienbarkeit

Pilotnutzer können einen Node, Endpoint und eine Connection ohne externe Schulung korrekt anlegen und in der Topologie finden.

## QO-007 Datenminimierung

Keine Kernfunktion benötigt Patientendaten.
