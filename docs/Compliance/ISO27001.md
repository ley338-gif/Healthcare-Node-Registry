# ISO/IEC 27001 Alignment

## Status

Vorbereitung und Alignment – keine Zertifizierung und keine Konformitätsbehauptung.

## Ziel

Das Projekt stellt kontrollierte Entwicklungs- und Betriebsnachweise bereit, die in ein organisationsweites ISMS eingebettet werden können.

## Arbeitsbereiche

| Bereich | Projektartefakt/Nachweis |
|---|---|
| Kontext und Scope | ProductVision, Scope, Deployment Architecture |
| Führung und Verantwortlichkeit | Rollen in Dokumenten, Freigaben |
| Risiken und Chancen | RiskRegister |
| Sicherheitsziele | QualityObjectives und Security Backlog |
| Kompetenz und Bewusstsein | Engineering Manual, Reviewchecklisten |
| Dokumentierte Information | versionierte Repository-Dokumente |
| Betriebsplanung | Release-, Update-, Backup- und Incident-Prozess |
| Lieferanten/Abhängigkeiten | Dependency Register, SBOM |
| Leistungsbewertung | Metriken, Reviews, Audits |
| Verbesserung | CAPA, Lessons Learned, Technical Debt |

## Produktbezogene technische Themen

- Zugriffskontrolle
- Kryptografie/TLS
- sichere Entwicklung
- Logging und Monitoring
- Schwachstellenmanagement
- Backup und Wiederherstellung
- Konfigurationsmanagement
- Lieferkettensicherheit
- Incident-Unterstützung
- Datenminimierung

## Wichtige Abgrenzung

ISO/IEC 27001 bewertet das Informationssicherheitsmanagementsystem einer Organisation. Software allein kann nicht „ISO-27001-zertifiziert“ sein. Kundenkonfiguration, Betrieb, Personal, Lieferanten und Prozesse bleiben wesentlich.
