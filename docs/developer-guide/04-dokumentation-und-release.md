# Dokumentation und Releasebeitrag

Jede produktrelevante Änderung aktualisiert die betroffenen Benutzer-, Administrator-, Architektur-, DICOM- oder API-Inhalte. Geplantes darf nicht als implementiert beschrieben werden.

Dokumente verwenden die Frontmatter- und Statusregeln der [Masterspezifikation](../DOCUMENTATION_MASTER_SPECIFICATION.md), relative Links und konsistente Terminologie. Architekturentscheidungen werden als ADR, betreiberrelevante Änderungen in Release Notes und bekannte Einschränkungen im passenden Handbuch dokumentiert.

Ein Entwicklungsbeitrag ist erst freigabefähig, wenn Implementierung, Tests, Migration, Dokumentation, Changelog und Sicherheitsfolgen gemeinsam geprüft wurden.
